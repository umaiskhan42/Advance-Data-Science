# Object detection on MD-AS-2025 — frozen DINOv3 vs the dataset paper

Generated by `scripts/od_01_prepare.py` and `scripts/od_03_dinov3_detector.py`.
Task: detect the five microfauna taxa in the annotated full-frame microscopy
images (Dataset A: 4,000 frames, 5,821 boxes), split 3,600 train / 400 val to
match the dataset paper.

## Method — keeping the project on ONE frozen backbone

Consistent with the rest of the project (and with the lab's "frozen feature
extractor" theme), detection also uses **DINOv3 ViT-S/16, frozen**:

- the backbone's 28×28×384 patch features (448-px input) are extracted **once**
  and cached to disk (`data/processed/od/feat_{train,val}.npy`);
- only a **lightweight anchor-free head** (objectness + 5-class + box, per grid
  cell) is trained on those cached features — 80 epochs, CPU, minutes.

AP@0.5 is computed with a self-contained implementation (greedy IoU matching,
all-point AP), so results need no external mAP library.

## Result

| Taxon | Frozen DINOv3 + head (ours) | MD-AS-2025 paper (YOLOv5/v8) |
|---|---|---|
| Arcellinida | 0.444 | 0.958 |
| Hypotrichida | 0.539 | 0.991 |
| Digononta | 0.212 | 0.916 |
| Monogononta | 0.151 | 0.834 |
| Nematoda | 0.065 | 0.778 |
| **Overall mAP@0.5** | **0.282** | **0.895** |

→ `results/csv/od_dinov3_per_class_ap.csv`,
`results/csv/od_methods_comparison.csv`,
`results/figures/od_dinov3_vs_paper.png`,
`results/figures/od_dinov3_predictions.png`.

## Why this is the expected, honest picture

- The paper's number comes from a **fully end-to-end-trained, multi-scale**
  detector (YOLOv5/v8: backbone + neck + head all optimised for localisation).
- Ours uses a **frozen** backbone with a **single-scale, lightweight head** and
  **no fine-tuning at all** — the same constraint that makes the anomaly-detection
  result notable here *limits* localisation precision.
- The pattern across taxa is interpretable: large, compact, high-contrast taxa
  (Hypotrichida 0.54, Arcellinida 0.44) are detected best; the **thin, elongated
  Nematoda** (0.065) is hardest, because a single-cell, center-assigned box
  regressor struggles to hit IoU ≥ 0.5 on a long thin worm.

**Take-away:** frozen DINOv3 features are excellent for *image-level* judgements
(anomaly detection AUROC ≈ 0.79) but, without fine-tuning or a multi-scale head,
trail a trained detector on *precise box localisation*. This cleanly delineates
where a frozen foundation model helps most.

## Note on a YOLOv8 reproduction

A from-scratch YOLOv8 reproduction in our environment was attempted
(`scripts/od_02_train_eval.py`) but is **computationally impractical on this
CPU-only machine**: ~13–20 min per epoch (≈6 s/iter × 225 batches at 512 px),
i.e. 6–10 h for 30 epochs. We therefore use the **dataset paper's published
YOLOv5/v8 benchmark (0.895)** as the trained-detector reference rather than an
under-trained CPU run. The script is provided and will reproduce the YOLO numbers
on a GPU:

```bash
OD_MODEL=yolov8n.pt OD_IMGSZ=640 OD_EPOCHS=100 python scripts/od_02_train_eval.py
```

Two readings worth noting:
- **Fig. 6** reproduces the paper's morphology trend — Nematoda are largest
  (~260×268 px median ~232²), Arcellinida smallest (~121×122) and most circular
  (tight width≈height diagonal); Digononta larger than Arcellinida.
- **Fig. 5** confusion matrix shows that *when the frozen-DINOv3 detector fires it
  assigns the right taxon* (strong diagonal, little taxon-to-taxon confusion); the
  errors concentrate in the `background` column — i.e. missed objects (low recall),
  which is exactly what caps the mAP. CSVs: `paper_fig5_confusion_matrix.csv`,
  `paper_fig6_pixel_dimension_stats.csv`.

## How to improve the frozen-DINOv3 detector (future work)
- multi-scale features (FPN over several ViT blocks) instead of one 28×28 grid;
- assign each box to a neighbourhood of cells (more positives) + CIoU loss;
- higher input resolution (helps the thin Nematoda);
- light fine-tuning of the last DINOv3 blocks (departs from "fully frozen").
